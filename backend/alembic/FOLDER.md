# backend/alembic/

## Purpose
Alembic database migration management. Migrations are run automatically at server startup via `storage.init_db()` (which calls `alembic upgrade head`). Can also be run manually with `cd backend && alembic upgrade head`.

## Subfolders
| Folder | Role |
|---|---|
| `versions/` | Individual migration scripts, numbered sequentially |

## Key Files
| File | Purpose |
|---|---|
| `env.py` | Alembic environment — configures the async SQLAlchemy engine from `Settings.database_url` |
| `script.py.mako` | Template for new migration files generated by `alembic revision` |

## Last Session Changes
**Session date:** 2026-04-29

**Changes made:**
- `versions/0002_style_posts_linkedin.py` — new migration creating 4 tables for the Post Studio feature

**Reason:** Post Studio requires persistent storage for the style corpus (`style_samples`), the distilled profile (`style_profile`), generated drafts (`generated_posts`), and the LinkedIn OAuth token (`linkedin_account`).

**Outcome:** Migration file created and verified to parse cleanly. Apply with `alembic upgrade head`.

**Watch out for:** The `style_profile` and `linkedin_account` tables use a singleton pattern (primary key always = 1). Alembic does not enforce this — it is enforced in application code (`storage.py` upsert helpers).
